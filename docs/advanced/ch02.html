2장. 준비 - DB 와 Kafka 켜기, 프로젝트 열기

학습 목표

  • advanced/docker-compose.yml 로 PostgreSQL 과 Kafka 를 함께 켠다.
  • Kafka 컨테이너 안의 명령어로 토픽을 살펴본다.
  • 기초 과정에서 무엇이 바뀌었는지 파일 목록으로 확인한다.

2-1. docker-compose.yml - DB 에 Kafka 를 더하다

📄 advanced/docker-compose.ymlGitHub 에서 보기
# =====================================================================
# MSA 심화 - 데이터베이스(PostgreSQL 18) + Kafka
#
#   시작        : docker compose up -d        (이 파일이 있는 advanced 폴더에서)
#   상태 확인   : docker compose ps           (db 가 healthy, kafka 가 Up 이면 준비 완료)
#   멈추기      : docker compose stop         (데이터는 남는다)
#   완전히 지우기: docker compose down -v      (컨테이너 + 데이터 볼륨 삭제, 되돌릴 수 없음)
#
# 접속 정보
#   PostgreSQL : localhost:5436 / postgres / postgres / DB 2개 userdb, postdb
#   Kafka      : localhost:9092
#
# 기초 과정(저장소 맨 위 폴더)의 DB(mas-db, 5435)와 이름·포트를 다르게 해서
# 두 과정의 데이터가 섞이지 않게 했다. 둘을 동시에 켜 두어도 괜찮다.
# =====================================================================

name: react-spring-mas-advanced

services:
  db:
    image: postgres:18
    container_name: mas-adv-db
    restart: unless-stopped
    ports:
      - "5436:5432"                   # 내 PC 5436 → 컨테이너 5432
    environment:
      POSTGRES_USER: postgres
      POSTGRES_PASSWORD: postgres     # 실습용 비밀번호
      TZ: Asia/Seoul
    command: ["postgres", "-c", "timezone=Asia/Seoul"]
    volumes:
      - mas_adv_data:/var/lib/postgresql
      # 처음 켤 때 한 번 실행 → userdb, postdb 생성 (기초 과정과 같은 init.sql)
      - ./db:/docker-entrypoint-initdb.d
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U postgres -d postdb"]
      interval: 5s
      timeout: 3s
      retries: 20

  # -------------------------------------------------------------------
  # Kafka - 서비스끼리 "소식(이벤트)" 을 전하는 우체국
  #
  #   apache/kafka 이미지는 설정을 하나도 주지 않으면 "혼자서 도는 Kafka 1대(KRaft 방식)" 로
  #   켜진다 (주소 localhost:9092). 공부용으로는 그것으로 충분하므로 메모리 크기만 정해 준다.
  #   토픽(user-events)은 따로 만들지 않는다. 처음 쓰일 때 Kafka 가 자동으로 만든다.
  # -------------------------------------------------------------------
  kafka:
    image: apache/kafka:4.3.2
    container_name: mas-adv-kafka
    restart: unless-stopped
    ports:
      - "9092:9092"                   # 내 PC 9092 → 컨테이너 9092
    environment:
      KAFKA_HEAP_OPTS: "-Xmx384m -Xms384m"   # 메모리를 384MB 로 줄여 실습 PC 부담을 덜어 준다

volumes:
  mas_adv_data:

Kafka 컨테이너에는 설정이 거의 없다. apache/kafka 이미지는 아무 설정도 주지 않으면 혼자서 도는 Kafka 1대로 켜지고, localhost:9092 로 접속하게 되어 있다. 메모리 크기(KAFKA_HEAP_OPTS)만 줄여 실습 PC 부담을 덜었다.

KRaft 가 뭔가요? 예전 Kafka 는 ZooKeeper 라는 프로그램을 하나 더 켜야 했다. Kafka 4 부터는 Kafka 가 스스로 관리하는 KRaft 방식만 쓴다. 그래서 컨테이너 하나면 된다.

2-2. 켜고 확인하기

[PS] advanced 폴더에서 (기초 과정의 DB 와 따로 켜진다)

docker compose up -d
docker compose ps

NAME            IMAGE                STATUS                   PORTS
mas-adv-db      postgres:18          Up 6 seconds (healthy)   0.0.0.0:5436->5432/tcp
mas-adv-kafka   apache/kafka:4.3.2   Up 6 seconds             0.0.0.0:9092->9092/tcp

Kafka 는 켜지는 데 10초쯤 걸린다. 준비됐는지는 로그로 본다.

[PS]

docker logs mas-adv-kafka | Select-String "Kafka Server started"

[2026-11-24 05:33:12,314] INFO [KafkaRaftServer nodeId=1] Kafka Server started (kafka.server.KafkaRaftServer)

토픽 목록 보기 - Kafka 이미지 안에 들어 있는 명령어(/opt/kafka/bin/...)를 docker exec 로 실행한다.

[PS]

docker exec mas-adv-kafka /opt/kafka/bin/kafka-topics.sh --bootstrap-server localhost:9092 --list

처음에는 아무것도 나오지 않는다. user-events 토픽은 서비스가 처음 쓸 때 Kafka 가 자동으로 만든다(자동 생성이 기본으로 켜져 있다). 4장에서 post-service 를 켠 뒤 다시 보면 user-events 가 생겨 있다.

2-3. IntelliJ 로 열기

기초 과정과 같다. 다만 advanced\backend 폴더를 연다.

  1. File → Open → react-spring-mas-postgresql\advanced\backend → OK → Trust Project
  2. Gradle sync 가 끝나면 mas-board-advanced 아래에 서비스 3개가 보인다. (처음에는 Kafka 라이브러리를 받느라 조금 더 걸린다)

기초 과정 서비스가 켜져 있다면 먼저 끈다. 두 과정 모두 8080~8082 포트를 쓴다. IntelliJ 창이 두 개 열려 있으면 헷갈리기 쉬우니, 기초 과정 창은 닫아 두자.

2-4. 기초 과정에서 바뀐 파일

서비스 파일 무엇을
user-service build.gradle spring-boot-starter-kafka 추가
application.yml Kafka 주소, DB 포트 5436, app.kafka.enabled 스위치
User.java changeNickname() 추가
AuthService.java changeNickname() - 저장 + 새 토큰 발급
AuthController.java PUT /api/auth/me - 저장 뒤 이벤트 보내기
새 NicknameRequest.java { "nickname": "..." } 요청
새 UserEvent.java 소식 JSON 모양
새 UserEventPublisher.java Kafka 로 소식 보내기
post-service build.gradle spring-boot-starter-kafka 추가
application.yml Kafka 주소, 컨슈머 그룹, DB 포트 5436, 스위치
Post.java writer 를 바꿀 수 있게 (updatable = false 뺌)
PostRepository.java updateWriter() - 한 회원 글의 writer 한꺼번에 바꾸기
새 UserEvent.java 소식 JSON 모양 (user-service 것과 따로)
새 UserEventListener.java Kafka 에서 소식 받기
React api.js, AuthContext.jsx updateMe(), changeNickname()
App.jsx, Layout.jsx, App.css /me 화면 연결, 머리글 닉네임을 링크로
새 pages/ProfilePage.jsx 내 정보 · 닉네임 바꾸기 화면

api-gateway 는 하나도 바뀌지 않았다. PUT /api/auth/me 는 이미 /api/auth/** 규칙으로 user-service 에 가고, 로그인이 필요한 주소로 검사된다. 새 기능을 넣어도 정문은 그대로다.

정리

  • advanced 폴더에서 docker compose up -d 하면 PostgreSQL(5436)과 Kafka(9092)가 함께 켜진다.
  • Kafka 명령어는 docker exec mas-adv-kafka /opt/kafka/bin/... 로 실행한다.
  • 토픽 user-events 는 처음 쓰일 때 자동으로 생긴다.
  • IntelliJ 로 advanced\backend 를 연다. 게이트웨이는 기초와 같다.

확인 문제

  1. Kafka 4 에서는 ZooKeeper 를 따로 켜지 않아도 되는 이유는?
  2. user-events 토픽을 만드는 명령을 따로 실행하지 않았는데도 토픽이 생기는 이유는?
  3. 닉네임 바꾸기 API 를 더했는데 게이트웨이를 고치지 않아도 되는 이유는?
