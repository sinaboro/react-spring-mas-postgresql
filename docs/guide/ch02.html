2장. DB 준비 - 컨테이너 하나에 DB 둘

학습 목표

  • PostgreSQL 컨테이너 하나 안에 데이터베이스 두 개(userdb, postdb)를 만든다.
  • docker-entrypoint-initdb.d 로 처음 켤 때 SQL 을 자동 실행하는 방법을 안다.
  • "DB 서버" 와 "데이터베이스" 의 차이를 설명할 수 있다.

2-1. DB 서버와 데이터베이스는 다르다

먼저 낱말부터 정리하자.

낱말 뜻 이 교안에서
DB 서버 PostgreSQL 프로그램이 돌아가는 곳 (컨테이너) mas-db 컨테이너 1개, 포트 5435
데이터베이스 DB 서버 안에 만드는 저장 공간. 테이블을 담는다 userdb, postdb 2개
테이블 데이터베이스 안의 표 userdb.users, postdb.posts

PostgreSQL 에서는 서로 다른 데이터베이스의 테이블을 한 SQL 로 JOIN 할 수 없고, 외래 키도 걸 수 없다. 같은 서버(컨테이너) 안에 있어도 마찬가지다. (dblink 같은 확장 기능을 따로 설치하면 억지로 이을 수는 있지만, 그러면 서비스끼리 다시 DB 로 묶이므로 MSA 에서는 쓰지 않는다) 그래서 컨테이너를 하나만 써도 "서비스마다 자기 DB" 원칙을 지킬 수 있다.

[MSA 개념] 왜 컨테이너를 하나만 쓸까?

실제 운영에서는 DB 서버까지 서비스마다 나누기도 한다. 하지만 실습 PC 에는 이미 서비스 3개와 React 가 떠 있다. 그래서 이 교안은 컨테이너 1개 + 데이터베이스 2개로 가볍게 간다. 서비스 코드는 똑같고, 나중에 DB 서버를 나누려면 application.yml 의 접속 주소만 바꾸면 된다.

2-2. docker-compose.yml

📄 docker-compose.ymlGitHub 에서 보기
# =====================================================================
# MSA 게시판 데이터베이스 (PostgreSQL 18) - 컨테이너 1개, 데이터베이스 2개
#
#   시작        : docker compose up -d        (이 파일이 있는 폴더에서)
#   상태 확인   : docker compose ps           (STATUS 가 healthy 이면 준비 완료)
#   멈추기      : docker compose stop         (데이터는 남는다)
#   완전히 지우기: docker compose down -v      (컨테이너 + 데이터 볼륨 삭제, 되돌릴 수 없음)
#
# 접속 정보
#   호스트 localhost / 포트 5435 / 사용자 postgres / 비밀번호 postgres
#   데이터베이스 2개
#     userdb : user-service 만 쓴다 (users 테이블)
#     postdb : post-service 만 쓴다 (posts 테이블)
#
# [MSA 개념] Database per Service - "서비스마다 자기 데이터베이스"
#   PostgreSQL 서버(컨테이너)는 하나지만, 그 안의 데이터베이스는 서비스마다 따로다.
#   서로 다른 데이터베이스의 테이블은 JOIN 할 수도, 외래 키(FK)를 걸 수도 없다.
#   → 서비스끼리 데이터베이스로 엮이지 않으므로 한 서비스를 고쳐도 다른 서비스가 깨지지 않는다.
#   실제 운영에서는 DB 서버(컨테이너)까지 나누기도 한다. 그래도 서비스 코드는 그대로이고
#   application.yml 의 접속 주소만 바꾸면 된다.
# =====================================================================

# 프로젝트 이름. 다른 교안(react-spring-postgresql)의 컨테이너와 섞이지 않게 이름을 따로 붙인다.
name: react-spring-mas-board

services:
  db:
    image: postgres:18
    container_name: mas-db
    restart: unless-stopped
    ports:
      - "5435:5432"                   # 내 PC 5435 → 컨테이너 5432
    environment:
      POSTGRES_USER: postgres
      POSTGRES_PASSWORD: postgres     # 실습용 비밀번호
      TZ: Asia/Seoul
    command: ["postgres", "-c", "timezone=Asia/Seoul"]
    volumes:
      - mas_data:/var/lib/postgresql
      # 컨테이너가 "처음" 만들어질 때 이 폴더의 .sql 파일을 한 번 실행한다 → userdb, postdb 생성
      # (이미 데이터가 있으면 다시 실행하지 않는다. 처음부터 다시 하려면 docker compose down -v)
      - ./db:/docker-entrypoint-initdb.d
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U postgres -d postdb"]
      interval: 5s
      timeout: 3s
      retries: 20

volumes:
  mas_data:

눈여겨볼 곳은 두 군데다.

  • POSTGRES_DB 가 없다. React 심화 과정 compose 파일에는 POSTGRES_DB: authboard 가 있어서 DB 하나가 자동으로 만들어졌다. 이번에는 DB 를 두 개 만들어야 하므로 아래 init.sql 에 맡긴다.
  • ./db:/docker-entrypoint-initdb.d - 내 PC 의 db 폴더를 컨테이너의 "처음 실행할 SQL 폴더" 에 연결한다.

2-3. init.sql - 데이터베이스 두 개 만들기

📄 db/init.sqlGitHub 에서 보기
-- init.sql - 데이터베이스 2개 만들기 (컨테이너가 처음 켜질 때 한 번만 자동 실행)
--
-- [MSA 개념] 서비스마다 자기 데이터베이스를 가진다 (Database per Service)
--   userdb : 회원 서비스(user-service) 전용  → users 테이블
--   postdb : 게시글 서비스(post-service) 전용 → posts 테이블
-- 테이블은 여기서 만들지 않는다. 각 서비스의 JPA(ddl-auto: update)가 Entity 를 보고 만든다.

CREATE DATABASE userdb;
CREATE DATABASE postdb;

PostgreSQL 공식 이미지는 데이터가 하나도 없을 때(처음 켤 때) /docker-entrypoint-initdb.d 폴더의 .sql 파일을 차례로 실행한다. 테이블은 여기서 만들지 않는다. 각 서비스가 켜질 때 JPA(ddl-auto: update)가 Entity 를 보고 자기 DB 에 테이블을 만든다.

주의 - init.sql 은 처음 한 번만 실행된다. 이미 데이터 볼륨이 있으면 다시 실행하지 않는다. init.sql 을 고쳤거나 DB 가 안 보이면 docker compose down -v 로 볼륨까지 지우고 다시 켠다. (모든 데이터가 지워진다)

2-4. 켜고 확인하기

[PS] 저장소 폴더에서

cd C:\study\react-spring-mas-postgresql   # docker-compose.yml 이 있는 저장소 맨 위 폴더
# up : docker-compose.yml 에 적힌 컨테이너(mas-db)를 만들고 켠다. 처음에는 postgres:18 이미지를 받느라 1~2분
# -d : 뒤에서(detached) 켜고 프롬프트를 바로 돌려준다. 없으면 DB 로그가 화면을 차지하고, 창을 닫으면 DB 도 꺼진다
docker compose up -d
# ps : 이 compose 파일로 켠 컨테이너의 상태. STATUS 가 (health: starting) → (healthy) 로 바뀔 때까지 몇 번 다시 쳐 본다
docker compose ps

NAME      IMAGE         COMMAND                   SERVICE   STATUS                    PORTS
mas-db    postgres:18   "docker-entrypoint.s…"   db        Up 11 minutes (healthy)   0.0.0.0:5435->5432/tcp

STATUS 가 healthy 이면 준비가 끝났다. 데이터베이스 목록을 보자.

[PS]

# docker exec <컨테이너> <명령> : 이미 켜져 있는 컨테이너 안에서 명령 하나를 실행한다 (내 PC 에 psql 을 설치하지 않아도 된다)
# psql : PostgreSQL 명령줄 도구.  -U postgres = postgres 사용자로,  -c "..." = 이 명령 하나만 실행하고 끝
# \l    : psql 의 "데이터베이스 목록(list)" 명령 → userdb, postdb 가 있어야 한다
docker exec mas-db psql -U postgres -c "\l"

   Name    |  Owner   | Encoding | ...
-----------+----------+----------+----
 postdb    | postgres | UTF8     | ...      ← init.sql 이 만든 것
 postgres  | postgres | UTF8     | ...      ← 기본 DB
 template0 | postgres | UTF8     | ...
 template1 | postgres | UTF8     | ...
 userdb    | postgres | UTF8     | ...      ← init.sql 이 만든 것

userdb 와 postdb 가 보이면 성공이다. 서비스를 아직 켜지 않았으므로 두 DB 안에는 테이블이 없다. 4·5장에서 서비스를 켠 뒤 다시 확인한다.

IntelliJ 나 DBeaver 로 접속할 때는 아래 값을 쓴다. 데이터베이스 이름만 바꿔 두 번 연결하면 된다.

항목 값
Host / Port localhost / 5435
User / Password postgres / postgres
Database userdb 또는 postdb

정리

  • DB 서버(컨테이너) 는 1개, 그 안의 데이터베이스는 userdb, postdb 2개다.
  • 서로 다른 데이터베이스 사이에는 JOIN·FK 가 안 된다 → 서비스끼리 DB 로 묶이지 않는다.
  • init.sql 은 데이터가 없을 때 처음 한 번만 실행된다.

확인 문제

  1. userdb 의 users 와 postdb 의 posts 를 한 SQL 로 JOIN 할 수 있는가?
  2. init.sql 에 CREATE DATABASE commentdb; 를 추가하고 docker compose up -d 를 다시 했는데 commentdb 가 안 보인다. 왜 그럴까? 어떻게 해야 할까?
  3. 나중에 DB 서버를 서비스마다 나누기로 했다. user-service 에서 바꿔야 하는 곳은 어디인가?
